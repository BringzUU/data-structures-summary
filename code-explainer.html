📌 ภาพรวมโปรแกรม

นี่คือโปรแกรม GUI (Swing) จำลองระบบ "รับเลี้ยงสัตว์" ประกอบด้วยโครงสร้างข้อมูล 3 แบบที่เขียนขึ้นเอง (ไม่ใช้ของ java.util):

LinkedList เก็บ Pet ที่รอรับเลี้ยง (doubly linked list)
Stack เก็บ Adopter ที่รอคิว (LIFO)
Queue เก็บ Adopter ที่ "รับเลี้ยงสำเร็จ" แล้ว (FIFO)

ผู้ใช้กดปุ่มบน GUI เพื่อ: สุ่มข้อมูล → เพิ่มเข้าโครงสร้าง → จับคู่ Pet กับ Adopter → เรียงลำดับ → บันทึก/โหลดไฟล์

Pet Model / Data Class

เก็บข้อมูลสัตว์เลี้ยงหนึ่งตัว

ฟิลด์ความหมาย
idรหัสสัตว์ (สุ่ม 10-99)
nameชื่อ (สุ่มตัวอักษร a-z)
type"cat" หรือ "dog"
ageอายุ (สุ่ม 2-21)

มี getter ครบทุกฟิลด์ และ override toString() เพื่อโชว์เป็น id,name,type,age

✅ ตอนนี้: implements Serializable แล้ว — จำเป็นเพราะ object นี้จะถูกเก็บลงไฟล์ผ่าน Queue (Adopter มี Pet อยู่ข้างใน)

Adopter Model / Data Class

เก็บข้อมูลผู้ขอรับเลี้ยง

ฟิลด์ความหมาย

✅ implements Serializable แล้ว

PNode Node ของ LinkedList (Pet)

โหนดของ doubly-linked list สำหรับเก็บ Pet หนึ่งตัว

PNode
 ├─ data : Pet     (ข้อมูลจริง)
 ├─ next : PNode   (โหนดถัดไป)
 └─ prev : PNode   (โหนดก่อนหน้า)

Constructor รับ Pet เข้ามาแล้วเซ็ต next, prev เป็น null ก่อนเสมอ

ANode Node ของ Stack & Queue (Adopter)

โครงสร้างเหมือน PNode ทุกอย่าง เพียงแต่เก็บ Adopter แทน Pet

ใช้ร่วมกันทั้งในคลาส Stack และ Queue ด้านล่าง

LinkedList เก็บ Pet ที่รอรับเลี้ยง

Doubly-linked list มี head, tail, size

add(Pet a)

สร้าง PNode ใหม่ แล้วต่อเข้าไปทาง ท้าย (tail) ของลิสต์ — ถ้าลิสต์ว่างให้ head = tail = node เลย

remove()

ลบสัตว์ตัวที่อยู่ ท้ายลิสต์ (tail) แล้วคืนค่ากลับไป — ถ้าลิสต์ว่างคืน null

✅ แก้แล้ว: ตอนนี้เช็คว่าถ้าลบจนไม่เหลือ node จะเซ็ต head = null ด้วย และถ้ายังเหลือจะตัด tail.next = null เพื่อไม่ให้มี dangling reference (เมื่อก่อนพลาดจุดนี้ ทำให้ add() ครั้งถัดไปพัง)

isEmpty(), size(), getHead(), toArray()

เมธอดช่วยมาตรฐาน — toArray() วนจาก head ไป next เรื่อยๆ แปลงเป็น Pet[] เพื่อเอาไปแสดงในตาราง

⚠️ ข้อสังเกต: add() เพิ่มที่ tail และ remove() ก็ลบที่ tail เหมือนกัน → พฤติกรรมจริงคือ Stack (LIFO) ไม่ใช่คิวปกติ ถ้าต้องการให้ "ตัวที่เพิ่มก่อนถูกจับคู่ก่อน" ต้องเปลี่ยนไปลบจาก head แทน

Stack เก็บ Adopter ที่รอคิว — LIFO

ใช้ singly-linked node (ANode) โดยมีแค่ top ตัวเดียว

  • push(Adopter A) — สร้างโหนดใหม่ วางไว้บนสุด (node.next = top; top = node;)
  • pop() — เอาตัวบนสุดออก (top = top.next) แล้วคืนค่า
  • isEmpty(), size(), getTop(), toArray() — เมธอดช่วยมาตรฐาน

ล่าสุดที่ push เข้ามาจะเป็นตัวแรกที่ถูก pop ออก (คนที่กด "AddAdopter" ทีหลังจะได้จับคู่กับสัตว์ก่อน)

Queue เก็บ Adopter ที่รับเลี้ยงสำเร็จแล้ว — FIFO

Doubly-linked list ของ ANode มี front และ last

  • offer(Adopter a) — เพิ่มเข้าทาง last
  • poll() — เอาออกทาง front (คนแรกที่เข้ามาก่อน) พร้อมเช็คกรณีเหลือ node เดียวให้เคลียร์ last ด้วย — เมธอดนี้เขียนถูกต้องแล้ว (ไม่มีบั๊กแบบที่เจอใน LinkedList.remove())
  • toArray() — แปลงเป็น Adopter[]
  • clear() — เคลียร์ทั้ง front, last, size

sortByid()

เรียงลำดับสมาชิกใน queue ตาม id จากน้อยไปมาก โดยใช้ Bubble Sort:

1. toArray()        → ดึงข้อมูลทั้งหมดออกมาเป็น array ก่อน
2. bubble sort       → เรียงตาม id (วน 2 loop เทียบทีละคู่ สลับถ้าลำดับผิด)
3. clear()           → ล้าง queue เดิมทิ้งให้หมด
4. offer() วนใหม่    → เติมสมาชิกที่เรียงแล้วกลับเข้า queue ตามลำดับ

เป็นวิธี "แปลงเป็น array → sort → ใส่กลับ" ซึ่งใช้ได้ผล แม้จะไม่ efficient เท่าการ sort linked list ตรงๆ (แต่ข้อมูลจำนวนน้อยจึงไม่มีปัญหา)

NewJFrame หน้าต่างโปรแกรม (Swing GUI)

คลาสหลักที่รัน UI ประกอบด้วย 3 ตาราง (jTable1-3), 10 ปุ่ม, 2 ช่องข้อความ

ตัวแปรหลัก

  • list — Pet ทั้งหมดที่รอรับเลี้ยง (แสดงใน jTable1)
  • stack — Adopter ที่รอคิว (แสดงใน jTable2)
  • queue — คู่ Adopter+Pet ที่จับคู่สำเร็จ (แสดงใน jTable3)
  • currentPet, currentAdopter — ตัวที่เพิ่ง "สุ่ม" มา รอกดปุ่ม Add เพื่อใส่จริง

genPString() / genAString()

สุ่มสร้าง Pet / Adopter ใหม่ ด้วยค่าสุ่มตามช่วงที่กำหนดไว้ (id, ชื่อ, ประเภท, อายุ, เงินเดือน) — ยังไม่ถูกเพิ่มเข้าโครงสร้างข้อมูลใดๆ แค่สร้าง object รอไว้เฉยๆ

⚠️ id สุ่มแบบไม่เช็คซ้ำ (10-99) — ถ้าต้องใช้ id เป็น unique key ควรเพิ่ม logic กันชนกัน

updateTable1() / updateTable2() / updateTable3()

ล้างตารางเดิม (model.setRowCount(0)) แล้วดึงข้อมูลปัจจุบันจาก list/stack/queue ผ่าน toArray() มาเติมทีละแถว — เรียกใช้หลังทุกครั้งที่มีการเปลี่ยนแปลงข้อมูล เพื่อ sync หน้าจอกับข้อมูลจริง

initComponents()

โค้ด auto-generate จาก NetBeans GUI Builder — สร้างปุ่ม, ตาราง, layout ทั้งหมด ไม่ควรแก้มือ (ตามคอมเมนต์ "do not modify")

💾 ระบบ Save / Load

ใช้ Java Object Serialization มาตรฐาน:

Save:  Queue → ObjectOutputStream → data.ser
Load:  data.ser → ObjectInputStream → Queue (cast กลับ)

เนื่องจาก Queue เก็บ ANode ซึ่งเก็บ Adopter ซึ่งเก็บ Pet — ทุกคลาสในสายนี้ต้อง Serializable หมด ไม่งั้นจะ error ทันทีตอน writeObject()

💡 หมายเหตุ: data.ser จะถูกสร้าง/อ่านที่ working directory ของโปรแกรม (มักจะเป็นโฟลเดอร์ project ตอนรันจาก IDE) — ถ้า Load แล้วหาไฟล์ไม่เจอจะโชว์ dialog "Load error: ..."

🛠️ สรุปจุดที่แก้ไปแล้ว / ที่ยังควรพิจารณา

✅ แก้แล้วในเวอร์ชันนี้

  • เพิ่ม implements Serializable ให้ Pet, Adopter, PNode, ANode, LinkedList, Stack, Queue — ทำให้ Save/Load ทำงานได้จริง
  • LinkedList.remove() เซ็ต head = null เมื่อลบ node สุดท้าย และตัด tail.next = null กัน dangling reference

⚠️ ยังควรพิจารณาเพิ่ม (ไม่ใช่บั๊กที่ทำให้พัง แต่เป็นจุดออกแบบ)

  • LinkedList ทำงานแบบ LIFO ไม่ใช่ FIFO — ถ้าต้องการให้ Pet ที่เพิ่มก่อนถูกจับคู่ก่อน ต้องแก้ remove() ให้ลบจาก head แทน tail
  • id สุ่มไม่กันชนกัน — สองตัวอาจได้ id ซ้ำกันได้ ถ้าต้องใช้ id เป็นตัวอ้างอิงเฉพาะควรเช็คซ้ำก่อนสุ่มเสร็จ
  • ชื่อคลาส LinkedList, Stack, Queue ซ้ำกับ java.util — ตอนนี้ไม่พังเพราะไม่ได้ import java.util.* แต่เสี่ยงเกิด ambiguity ถ้ามีการ import เพิ่มในอนาคต แนะนำเปลี่ยนชื่อ เช่น PetList, AdopterStack, AdopterQueue
  • RemovePet / RemoveAdopter ไม่แจ้งเตือนผู้ใช้เมื่อว่าง — ปุ่มอื่นๆ (เช่น Addpet) มีการเช็ค null แล้วโชว์ข้อความ แต่สองปุ่มนี้ไม่มี ถึงจะไม่ error (เพราะ remove()/pop() เช็ค isEmpty() ให้แล้ว) แต่ผู้ใช้จะไม่รู้ว่ากดไปแล้วไม่มีอะไรเกิดขึ้น
